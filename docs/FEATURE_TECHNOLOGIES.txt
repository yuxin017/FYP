FEATURE / TECHNOLOGY / ENTRY POINT

Accounts: Firebase Auth + Firestore; email/password sign-in;
local_auth OS biometric session unlock; six-digit email OTP/password recovery
with one-time Firebase reset grants and legacy action-link support;
Profile -> Security & Account, and the email login screen.

Tickets: shared Firebase orders/tickets, validated guest/date/pricing, point
redemption, campaign limits, persistent uncertain-checkout recovery, QR/NFC,
PDF receipts and unified purchase history. Ticket confirmations do not charge
a bank/card, as agreed. Foreign confirmations use actual dated rates, trusted
15-minute quotes and saved currency/amount/rate snapshots in history/receipts.

Virtual Queue: transaction-based individual and group reservations, capacity
guards, height/ticket checks, reminders, cancellation, staff check-in, completed
visit ratings, loyalty credit and configurable repeated-no-show deductions.
The first missed reservation does not deduct points. Staff configure a 2–20
miss threshold; deductions start at that count and never exceed the balance.
Concurrent jobs settle each reservation once and release its reserved capacity.
Reservation reminders: scheduled OS notifications on Android/iOS and encrypted
Web Push in supported browsers. Enable under Profile -> Security & Account ->
Notifications, then opt in per reservation. Android requests notification and
alarm permission; its receivers restore schedules after reboot. Native schedules
work without the Node process once saved. Web delivery requires the running Node
backend, internet and browser notification support. Focus/force-stop/power settings
can affect delivery. Cancellation updates and sign-out remove device reminders;
native changes made elsewhere synchronize when the device next opens the app.
Browser jobs recheck the live reservation and account before sending, expire at
the return-window start and deduplicate retries. Signing keys are stored privately
in Firebase, so another clone loads the same service configuration automatically.

Groups: rotating invitations, registered/guest members, separate ticket links,
atomic multi-member booking, opt-in live location with expiry and cleanup.

Crowd heatmap: Python/scikit-learn Gaussian KernelDensity. Separate views use
confirmed queue demand or recent voluntarily shared GPS positions.
Movement and peak hours are aggregated without visitor identities. Live
positions expire after two minutes and movement samples after 24 hours.
TAR UMT Penang bounds and a Mapbox public token are configured in shared
Firebase settings; live tiles and the campus map were verified on 2026-11-10.

Recommendations: Python TF-IDF catalogue vectors + cosine nearest neighbours,
saved interests and the visitor's actual highly rated visits. Height, closure,
existing bookings, capacity and time-window rules still govern the itinerary.

Park Assistant: English/Malay/Chinese catalogue/help retrieval using TF-IDF,
feature links, real browser/Android speech input and text-to-speech output.
It uses current catalogue values instead of inventing prices, waits or venues.

Landmark camera: OpenCV ORB feature matching with RANSAC geometry checks and
ambiguity rejection. Admin -> Landmark References supplies real venue images;
Map -> Locate a Landmark confirms the detected starting point.

Live attraction cameras: MediaPipe EfficientDet Lite2 detects people on the
Android device. It checks overlapping crops for smaller people and merges
duplicate detections. A Gaussian heatmap concentrates near each detected torso.
The browser receives the video and heatmap via WebRTC. Firestore manages
staff-only attraction assignment and camera pairing.
See FINISH_SETUP.txt for the two-phone walk test.
Smart Photos: OpenCV YuNet detection + SFace embeddings, explicit opt-in selfie
enrolment, private templates/originals, watermarked matching galleries, optional
photo codes, real image edits, trusted pricing, points, purchase entitlements,
digital downloads and SMTP delivery connection.

Photo kiosk: separate visitor shopping/sign-in session, same-project purchases
and points, private QR/NFC print requests, actual edits/PDF print jobs and an
explicit physical collection step. Printer/NFC hardware needs hands-on checks.

Admin: visitor/access management, support conversations/private notes, ticket
packages/orders, facilities/slots, ride entry, photographers, campaigns/rewards,
loyalty/photo/weather policies, date-range sales/admission/top-ten/PDF reports.
Weather policies issue compensation automatically after an eligible observation;
private cursor batches resume safely and voucher grants are idempotent.
Crowd Monitoring refreshes queue demand, peak check-in hours and aggregated
same-pass journeys. Staff can move directly into facility availability controls.
Reports include voucher issuance, actual use events and cohort redemption rates.

Unusual Activity: Python IsolationForest after at least 20 active visitor
samples, plus explicit cancellation/missed-visit/device-session review rules.
Signals are for staff review; they do not automatically suspend an account.

Runtime: authenticated Node 22 application API uses the existing real Firebase
project. The chosen presentation setup keeps Firebase Spark and runs Node/Python
on the presentation PC. Cloud Functions deployment is not required for that
setup; USE_FIREBASE_FUNCTIONS stays false. Phone/SMS authentication was removed
at the user's request. Profile phone numbers are contact details only.
Python runs as a local JSON-lines worker. Provider settings are shared through
Firebase. Server-only email credentials load into backend memory and are passed
privately to the mail worker. SMTP sign-in from the shared source is verified;
the user confirmed password-OTP and purchased-photo inbox delivery on 10 November
2026. The launcher retrieves client
settings automatically, without copying env.json or a local email settings file.
Isolated automated checks are separate from the running application.
